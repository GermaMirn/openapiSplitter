## Архитектура

Проект использует **Feature-Sliced Design (FSD)** - методологию организации фронтенд кода, которая обеспечивает:

- **Масштабируемость** - легко добавлять новые фичи без изменения существующего кода
- **Предсказуемость** - четкая структура папок упрощает навигацию и поиск кода
- **Изоляция** - фичи изолированы друг от друга, что упрощает тестирование и поддержку
- **Переиспользование** - общие компоненты и утилиты доступны на всех уровнях

### Почему Feature-Sliced Design?

1. **Масштабируемость** - структура легко расширяется при росте проекта
2. **Поддерживаемость** - четкое разделение по слоям упрощает понимание кода
3. **Командная работа** - разные разработчики могут работать над разными фичами без конфликтов
4. **Тестируемость** - изоляция фич упрощает написание тестов

## Слои архитектуры

### 1. App Layer (Слой приложения)

**Ответственность**: Инициализация приложения, провайдеры, роутинг.

**Что здесь находится:**
- **App.tsx** - корневой компонент приложения
- **index.tsx** - точка входа, рендеринг в DOM

**Правила:**
- Только инициализация и настройка
- Провайдеры (PrimeReact, роутер, state management)
- Не содержит бизнес-логики

### 2. Pages Layer (Слой страниц)

**Ответственность**: Композиция виджетов и фич в полноценные страницы.

**Что здесь находится:**
- Компоненты страниц, которые собирают виджеты и фичи
- Роутинг и навигация

**Правила:**
- Только композиция, без бизнес-логики
- Использует виджеты и фичи
- Может использовать entities и shared

### 3. Widgets Layer (Слой виджетов)

**Ответственность**: Сложные составные компоненты, объединяющие несколько фич.

**Что здесь находится:**
- Виджеты - крупные UI блоки (например, FileTree, CodeViewer)
- Композиция фич и entities

**Правила:**
- Использует features и entities
- Может использовать shared
- Не содержит бизнес-логики

### 4. Features Layer (Слой фич)

**Ответственность**: Бизнес-фичи приложения, пользовательские сценарии.

**Что здесь находится:**
- Фичи - конкретные пользовательские сценарии
- Компоненты с бизнес-логикой
- Хуки для работы с данными

**Правила:**
- Использует entities и shared
- Содержит бизнес-логику фичи
- Изолированы друг от друга

### 5. Entities Layer (Слой сущностей)

**Ответственность**: Бизнес-сущности приложения.

**Что здесь находится:**
- Модели данных
- Компоненты для отображения сущностей
- Хуки для работы с сущностями

**Правила:**
- Использует только shared
- Не зависит от других слоев
- Переиспользуется в features и widgets

### 6. Shared Layer (Общий слой)

**Ответственность**: Переиспользуемые ресурсы, доступные на всех уровнях.

**Что здесь находится:**
- **api/** - API клиенты и настройки
- **config/** - конфигурация приложения
- **ui/** - базовые UI компоненты
- **styles/** - глобальные стили

**Правила:**
- Не содержит бизнес-логики
- Может использоваться любым слоем
- Не должен создавать циклические зависимости

## Поток данных

```
User Interaction
    ↓
Pages (композиция)
    ↓
Widgets (составные компоненты)
    ↓
Features (бизнес-логика)
    ↓
Entities (модели данных)
    ↓
Shared/API (запросы к серверу)
    ↓
Backend Services
```

**Пример потока для загрузки OpenAPI спецификации:**

1. **User Interaction** → Пользователь загружает файл на странице
2. **Page** → Композиция виджета FileUploader
3. **Widget** → Использует фичу UploadOpenAPISpec
4. **Feature** → Вызывает API через shared/api
5. **API** → Отправляет запрос к backend
6. **Response** → Данные проходят обратно через слои

## Принципы проектирования

### Правило импортов

**Импорты направлены только внутрь** - от внешних слоев к внутренним:

```
Pages → Widgets → Features → Entities → Shared
```

- Shared не импортирует ничего из других слоев
- Entities импортирует только из Shared
- Features импортирует из Entities и Shared
- Widgets импортирует из Features, Entities и Shared
- Pages импортирует из всех слоев

### Изоляция фич

Каждая фича изолирована и может работать независимо:

```typescript
// features/upload-spec/
//   ├── ui/
//   │   └── UploadSpecForm.tsx
//   ├── model/
//   │   └── useUploadSpec.ts
//   └── index.ts
```

### Переиспользование

Общие компоненты и утилиты находятся в Shared:

```typescript
// shared/ui/Button.tsx - используется везде
// shared/api/axios.ts - единая настройка API
```

## Разработка

### Установка зависимостей

```bash
bun install
```

### Запуск в режиме разработки

```bash
bun run dev
```

Приложение будет доступно по адресу: http://localhost:5173

### Сборка

```bash
bun run build
```

### Предпросмотр production сборки

```bash
bun run preview
```

### Проверка типов

```bash
# TypeScript проверка типов встроена в Vite
# Для отдельной проверки можно использовать:
npx tsc --noEmit
```

### Линтинг

```bash
bun run lint
```

### Тестирование

```bash
bun run test           # Запуск тестов (Vitest)
bun run test:watch     # Запуск в watch-режиме
bun run test:coverage  # Покрытие кода + HTML-отчёт (coverage/index.html)
```

Тесты используют Vitest, jsdom и @testing-library/react. Unit-тесты расположены в `test/unit/` по структуре FSD (features, shared/ui, widgets).

## Технологии

- **React 18** - основной фреймворк
- **TypeScript** - язык программирования с типизацией
- **Vite** - сборщик и dev server
- **React Router DOM** - маршрутизация
- **Zustand** - управление состоянием
- **PrimeReact + PrimeIcons** - UI библиотека
- **Tailwind CSS + PostCSS + Autoprefixer** - стилизация
- **Axios** - HTTP клиент
- **js-yaml** - парсинг YAML
- **Monaco Editor** (@monaco-editor/react) - просмотр и навигация по YAML файлам
- **Vitest + @testing-library/react + jsdom** - тестирование
